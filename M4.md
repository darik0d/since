## Step 1 (18:05-19:05): Reconnect email, from Telegram and web
Goal: one click from an alert to a ready, personal email showing the startup's progress since
the "not yet", previewed and then sent by the investor.

Data (migration 004):
- startups: add founder_name TEXT, founder_email TEXT (also add both fields to /new and the
  parse step; optional). Seed: Nordwind founder = "Mikko Nordwind (fictional)", email from env
  DEMO_FOUNDER_EMAIL if set, so the demo email lands in an inbox the user controls.
- reconnects: id, startup_id, created_at, to_email, subject, opener, ask, html, text,
  status ('draft'|'sent'), sent_at, smtp_message_id.

Entry points:
- Web: "Reconnect" button on the condition page and on the watchlist row, shown when at least
  one condition is confirmed or reported; primary (accent) when every non-"ask at check-in"
  condition is confirmed.
- Telegram: add a URL button "✉️ Reconnect" to Confirmed and Reported alerts. When the last
  non-ask condition of a startup becomes confirmed, send one extra alert:
  "🎯 <Startup> now meets everything you asked for" with buttons [Draft reconnect email] [Open].
- Both open /startups/[id]/reconnect?t=<token>, where token = HMAC-SHA256(startup_id, APP_SECRET)
  (hex, first 32 chars). The page and the send API reject a missing or wrong token.

Email content (template fills every fact; order matters):
1. Opener (LLM, 1 to 2 sentences, editable): congratulate on the most recent confirmed evidence.
2. "When we met at <met_where> on <met_on>, I said:" + the investor's exact original words,
   with the matched parts highlighted (reuse the highlight logic from the condition page).
3. Checklist, one row per condition, chip colors from globals.css:
   ✓ Confirmed: what + source name + date + link to the evidence URL.
   ◐ Founder-reported: same, labeled "founder-reported".
   ? Ask at check-in: rendered as a question ("How is burn looking?").
   Not met yet: "still open" (muted). Never hide unmet ones.
4. "Since then" timeline: Since's own evidence and timeline events for this startup, oldest
   first, each with date and source link. Then the Cala block from Step 2 when available.
5. Ask (LLM, 1 sentence, editable) + a button "Book 20 minutes" linking BOOKING_URL (hidden if unset).
6. Signature from settings (investor name, fund).
- HTML email: table layout, inline styles only, max-width 560px, Arial/Helvetica fallback for
  Inter, startup logo (logo_url) at the top if present. No JS, no external CSS. Plus a plain-text part.
- LLM input: only the facts list. LLM output: {subject, opener, ask} as JSON.

Preview page:
- Left: editable To (prefilled founder_email), Subject, Opener, Ask; "Regenerate" (LLM again).
- Right: live preview in an iframe (srcdoc) of the exact HTML that will be sent.
- Buttons: [Send] (only if SMTP_* set), [Copy HTML], [Open in Gmail]
  (https://mail.google.com/mail/?view=cm&fs=1&to=&su=&body= with the plain-text version).
- Send: POST /api/startups/[id]/reconnect/send with the token. nodemailer over SMTP
  (works with a Gmail app password: SMTP_HOST=smtp.gmail.com, SMTP_PORT=465). From = MAIL_FROM.
  Max 10 sends per hour. Store the reconnect row as 'sent' with the message id, add a timeline
  event "Reconnected", and show "Reconnected <time>" on the watchlist row.
- Never auto-send. Sending only ever happens from the Send button.

Done when: on the deployed app, after beat 2 the Telegram alert shows "✉️ Reconnect", the
preview shows quote + checklist + timeline, and Send delivers the email to DEMO_FOUNDER_EMAIL.

## Step 2 (19:05-20:05): Cala data
Cala = verified, sourced company data (headcount, funding rounds, investors, people, presence).
Use it to (a) verify two new condition types, (b) add a "Since you passed" block to the
reconnect email, (c) alert on new investors.

Client (src/lib/cala.ts, server only):
- Auth header X-API-KEY: CALA_API_KEY. Check docs.cala.ai for the REST paths first. If REST is
  unclear within 10 minutes, call the MCP endpoint https://api.cala.ai/mcp/ with
  @modelcontextprotocol/sdk (Client + StreamableHTTPClientTransport, header X-API-KEY) and use
  its tools: entity_search {name, entity_types, limit}, entity_introspection {entity_id},
  entity_retrieval {entity_id, properties, relationships}, knowledge_query {input}.
- Cache every response in table cala_cache (key, json, fetched_at), TTL 1 hour.
- Shapes verified at 17:45 on a real company (Fracttal):
  properties: employee_count {value, sources:[{name, document, date}]}, founding_date, website.
  outgoing PARTICIPATES_IN_CORPORATE_EVENT -> PrivateCompanyFundingRound with
  properties.event_date (sometimes missing), role ISSUER, sources with document URLs.
  incoming INVESTED_IN -> investors (name, sometimes properties.valid_since), FOUNDED,
  WORKS_AT (properties.role). Also HAS_PRESENCE_IN, HAS_HEADQUARTERS_IN, OPERATES_IN_INDUSTRY.
  Investors contain near-duplicates ("Kayyak" + "Kayyak Ventures", "RIVERWOOD" +
  "RIVERWOOD CAPITAL LP"): dedupe by normalized name prefix. Run entity_introspection on one
  funding round entity to see if amount/series exist before using them.

Entity match (migration 005: startups.cala_entity_id TEXT, startups.cala_match TEXT):
- On startup creation and via a "Find in Cala" button: entity_search by name (limit 5), then
  retrieve website for each. Auto-accept only when website matches the startup domain.
  Otherwise show the candidates (name + description) for the investor to pick, or "Not in Cala".
  Never auto-pick by name alone (Fracttal has a parent and a subsidiary entity).

Snapshots (migration 005: cala_snapshots(id, startup_id, entity_id, fetched_at, data_json)):
- data_json: employee_count + source name/date, rounds [{id, event_date, source urls}],
  investors [{name, valid_since}], presence [countries], hq, industry.
- Poll every 30 minutes for startups with cala_entity_id, plus on "Check now". Cala has no
  webhooks; this poll is its real-time part. Diff against the previous snapshot.

New mechanisms (only offered by the mapping LLM when CALA_API_KEY is set):
- funding_round: "come back when you've raised your next round / a seed / a Series A".
  Verifier: a Cala round with event_date after met_on (and matching series if Cala has it)
  -> confirmed, source_type independent, evidence URL = the round's first source document,
  label "via Cala (<source name>, <date>)".
- team_size: "come back when you're 20+ people". Verifier: employee_count >= N and the count's
  source date is after met_on -> confirmed, labeled "estimate via Cala (<source>, <date>)".
- Both go through the same status -> evidence -> timeline -> alert pipeline as webhooks.
- Presence in a country (HAS_PRESENCE_IN) is shown as supporting evidence on market_launch
  conditions only. It never flips a status on its own.

"Since you passed" block (reconnect email + condition page), only facts after met_on:
- Funding rounds with event_date after met_on (date, linked source).
- Investors with valid_since after met_on: "New investor: X". Without valid_since, do not call
  anyone "new".
- Headcount: current value with source and date. Show a delta ("8 -> 23") only against an
  earlier Cala snapshot that Since itself stored.
- Footer line: "Company data via Cala".

New-investor alert: when a snapshot diff shows a new investor, Telegram:
"🔔 New investor in <Startup>: <Investor> (via Cala)" + [Open].

Demo on a real company (Nordwind is fictional, so Cala is shown here): before 20:05, use
knowledge or entity search to pick a real startup where Cala lists a funding round after
2025-11-19. Candidate: Fracttal (Cala shows a round dated 2026-01-21 and investor Riverwood
valid since 2026-01-21; re-check live). Seed it as a clearly labeled example watch:
met at "Slush 2025" on 2025-11-19, words "Come back when you've raised your next round."
Check now -> funding_round confirmed via Cala -> reconnect preview shows the Cala block.

Done when: the example watch flips to Confirmed via Cala on the deployed app, and its reconnect
preview shows round + investor + headcount with sources.

## Step 3 (20:05-20:40): Inbound "not yet"s (one inbox, three sources)
Migration 006: inbound_items(id, source 'paste'|'email'|'granola', external_id, received_at,
sender, title, meeting_at, raw_text, extracted_json, status 'pending'|'accepted'|'dismissed'|'none',
startup_id NULL, UNIQUE(source, external_id)).

Extractor (src/lib/inbound.ts), one function for all sources:
- LLM JSON: {found, startup_name, startup_domain, founder_name, founder_email, met_on, quote,
  conditions_text}. quote = the investor's "not yet / come back when" words, verbatim.
- Deterministic guard: quote must be an exact substring of raw_text (after whitespace
  normalization). If not, status 'none' with a note. This blocks invented quotes.
- found=false -> status 'none' (kept for the log, hidden from the inbox).

Inbox page /inbox (sidebar item with a pending count):
- Cards: source badge (Email / Meeting notes / Pasted), title, sender, date, the quote.
- [Start watching] -> /new prefilled (startup, domain, founder, met_on, words) -> the existing
  parse + confirm flow. [Dismiss].
- "Paste an email or notes" textarea at the top (source 'paste'). This is also the demo fallback.
- Telegram on each new pending item: "📥 New 'not yet' from <source>: “<quote>”" + [Review].

Email adapter: POST /api/inbound/email (Postmark inbound webhook JSON).
- Auth: HTTP basic auth that Postmark sends from credentials in the webhook URL; compare with
  INBOUND_EMAIL_BASIC. Reject otherwise.
- Accept only when FromFull.Email is in INVESTOR_EMAILS (the investor forwards or BCCs their own
  pass email). external_id = MessageID. Text = TextBody (handle forwarded messages: the
  investor's words may be below "Forwarded message").
- Founder email: from the original To/Cc when present.
- Settings shows INBOUND_EMAIL_ADDRESS with a copy button: "Forward or BCC your pass emails here."

Done when: forwarding a pass email to the Postmark address creates a pending card and a
Telegram ping within a minute, and pasting text does the same.

## Step 4 (20:40-21:00): Granola meeting notes
- REST, read-only, base https://public-api.granola.ai, header Authorization: Bearer GRANOLA_API_KEY
  (grn_...). Docs: https://docs.granola.ai/llms-full.txt (read it for exact params).
- GET /v1/notes?created_after=<ISO>&cursor=<c> (paginated, max 30 per page), then
  GET /v1/notes/{id}?include=transcript. If it returns TRANSCRIPT_TOO_LARGE, page through
  GET /v1/notes/{id}/transcript.
- Only notes with a finished AI summary and transcript are returned, so a note appears a short
  while after the meeting ends.
- Rate limit about 5 requests/second: sleep 250 ms between calls.
- Poll every 10 minutes + "Sync now" button in Settings. Store the last sync time in settings.
  external_id = note id. Feed summary + transcript to the same extractor (source 'granola').
- Privacy: if GRANOLA_FOLDER_ID is set, only sync notes in that folder. Settings text:
  "Only meetings in your Since folder in Granola are read."
- Do not build Granola webhooks (Business/Enterprise only; polling is enough).

Done when: a 2-minute mock call recorded in Granola ("come back when you have a paying
enterprise customer") shows up in /inbox after Sync now.
